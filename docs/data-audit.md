# 資料一致性巡檢

`Data consistency audit` 工作流程約每 15 分鐘及 Pages 成功發布後讀取正式 Worker API。
預設範圍直接讀取 `js/config.js` 的指數與自選股；瀏覽器個人清單不會上傳或納入。

檢查包括報價與來源時間、依交易日判斷新鮮度、同來源同時間的正常盤比價、
盤前／正常盤前收基準、盤後正常盤收盤基準，以及官方年度日曆與公告查核。
不修改行情、不用不同時間的價格判定矛盾，也不把未提供的延長時段資料算成通過。
本巡檢不涵蓋所有歷史指標、新聞或夜盤報價，亦非獨立資料源的正確性認證。

結果寫入 `data/audit.json`，首頁顯示狀態與台北時間，展開後可查看未通過項目。
單次異常是 pending；同項目在 45 分鐘內再次出現且兩次至少相隔一分鐘才升級 warning。
恢復正常或超過 45 分鐘便重新計算次數。網路暫時失敗會重試一次，每次最多三個並行請求。
報告超過 45 分鐘會在瀏覽器顯示逾時，避免排程停止後仍留下綠燈。

工作流程先發布結果，再以失敗狀態標記持續異常；未另行設定電子郵件或其他訊息通知。
巡檢自己的報告提交會被發布後觸發器排除，防止部署迴圈。
每次推送只提交巡檢報告，並以 rebase 保留其他自動資料更新。

手動執行：`node scripts/run-data-audit.mjs`（會讀取正式 API 並更新本機報告）。
回歸測試：`node --test worker/test/data-audit.test.mjs`。
雲端手動執行：在 GitHub Actions 選取 Data consistency audit → Run workflow。
